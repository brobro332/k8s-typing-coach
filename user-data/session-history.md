# 💬 [k8s-typing-coach] 세션 히스토리 & 설계 의사결정 기록

이 문서는 프로젝트 시작부터 현재까지 **학습자와 AI 코치 간에 나눈 모든 대화 맥락, 아키텍처 진화 과정, 보안 합의 사항, 그리고 학습 진도**를 기록한 문서입니다. 다른 컴퓨터에서 `git pull`을 받은 뒤 이 문서를 읽거나 AI에게 참고하게 하면 즉시 이어서 진행할 수 있습니다.

---

## 📅 1. 프로젝트 탄생 배경과 3대 초기 요구사항
* **사용자 요청**:
  1. 지정된 워크스페이스 폴더 외에 다른 폴더는 절대 확인하거나 건드리지 말 것.
  2. 개념도 명령어도 하나도 모르는 완전 초심자를 걸음마부터 가르치는 쿠버네티스(K8s) 가이드라인을 제공할 것.
  3. 기본적으로 내가 읽기 쉬운 구조이면서, 나중에 DB화해서 어떤 사람이라도 K8s를 밑바닥부터 공부할 수 있는 코칭 프로그램으로 가공할 수 있는 형태일 것.

* **아키텍처 확장 설계 (모듈형 지식 그래프 & 시나리오 엔진)**:
  - 단방향 강의록 대신 **개념 사전(`dictionary/concepts/`)**, **명령어 사전(`dictionary/commands/`)**, **독립 실습 유닛(`labs/`)**, **커리큘럼 트랙(`tracks/`)**을 분리하고 ID로 연결하는 관계형/그래프 DB 친화적 구조 채택.
  - 각 개념 문서는 `Lv.1 걸음마 식당 비유` -> `Lv.2 실습 핵심 원리` -> `Lv.3 실무/면접 아키텍처 정의`의 3단계 다중 레이어로 작성.

## ⌨️ 2. "복붙 금지! 직접 타이핑(Muscle Memory)" 시스템 도입
* **사용자 아이디어**: *"최대한 복붙이 아니라 타이핑해서 진행하고 싶은데 이런 요소는 추가할 수 없나?"*
* **구현된 장치**:
  1. **가이드 문서(`README.md`) 내 복사 버튼 제거 및 어절 해부표 도입**: 명령어를 통째로 복사하지 못하게 표로 쪼개고, 어순(`무전기` + `동사` + `대상`)과 발음 팁을 제공.
  2. **1:1 인터랙티브 타이핑 코치 (`coach.ps1`)**:
     - `Stopwatch`로 입력 시간을 측정해 기준 시간(ms)보다 빠르면 **`🚨 [복붙 감지 경보!]`**를 띄우고 다시 치게 함.
     - 초보자가 자주 내는 오타(`kubctl`, `kubeclt`, `ngnix` 등)를 잡아내어 맞춤형 힌트를 제공.
  3. **소통 방식 합의**: 사용자는 타이핑 피로도를 줄이기 위해 편한 반말/단문으로 질문하고, AI는 친절하고 명확한 코치 톤으로 답변하기로 함.

## 🛠️ 3. 완전 초보자의 실제 진입장벽 해결 과정 (FAQ 자산화)
1. **터미널 선택 (`concept-terminal.md`)**
   - *"보통 터미널은 어떤 걸 쓰는 게 좋아?"*
   - 👉 별도 창을 띄우지 않고 에디터 내장 터미널(`Ctrl + ~`, PowerShell)을 쓰는 것이 실무 표준이자 가장 편리함을 안내.
2. **스크립트 실행법과 단축 런처 (`coach.bat`, `check.bat`)**
   - *"ps1은 어떻게 실행해?"*
   - 👉 현재 폴더를 뜻하는 `./`와 `Tab` 자동완성 요령을 설명하고, 긴 경로 대신 `./coach` 한 단어만 치면 윈도우 실행 정책(`ExecutionPolicy`)까지 우회해 바로 실행되는 루트 런처 도입.
3. **사전 환경 설치 가이드 (`INSTALL_GUIDE.md` & `./check`)**
   - *"사전 환경 설치 가이드는 어디 있어?"*
   - 👉 내 컴퓨터에 Docker와 `kubectl`, K8s 클러스터가 켜져 있는지 1초 만에 검사하는 `./check` 진단기와, 윈도우에서 `Docker Desktop` 하나로 쿠버네티스를 켜는 상세 설치 가이드(`labs/lab-000-orientation/INSTALL_GUIDE.md`) 구축.

## 🔒 4. GitHub 레포지토리(`k8s-typing-coach`) 보안 감사 및 다중 PC 연동
* **사용자 요청**: *"레포지토리명은 `k8s-typing-coach`로 갈 건데, 터미널 결과 등 보안적으로 문제 될 것들을 `.gitignore`에 목록화하고, 또 Git에 올린다면 보안 취약점이 있는지 확인해줘. 그리고 다른 컴퓨터에서 pull 받아서 바로 진행할 수 있게 해줘."*
* **적용된 보안 패치 및 하네스(Harness) 규칙**:
  1. **`.gitignore` 5중 방어막**:
     - 터미널 출력/덤프 로그(`*.log`, `*.out`, `*.dump`), 쿠버네티스 인증서(`*kubeconfig*`, `*.key`, `*.crt`), 로컬 Secret 파일(`*.secret.yaml`, `.env*`), 개인 진도 파일(`user-data/progress.json`) 업로드 원천 차단.
  2. **로컬 절대 경로 제거 (상대 경로 전환)**:
     - 모든 마크다운 링크와 스크립트에서 로컬 드라이브 경로 및 사용자 이니셜을 완전히 제거하고 상대 경로(`../..`, `%~dp0`, `$MyInvocation`)로 통일.
  3. **PowerShell `Invoke-Expression` 취약점 제거**:
     - 모든 `coach.ps1`에서 임의 명령어 주입 위험이 있는 `Invoke-Expression`을 제거하고, `& kubectl` 배열 인자 호출 방식으로 화이트리스트화.
  4. **다중 PC 즉시 이어하기 (`./coach [단계번호]`)**:
     - 다른 컴퓨터에서 `git pull` 후 `./coach 2`처럼 숫자를 붙여 실행하면 즉시 해당 단계로 점프하여 이어할 수 있도록 `coach.bat` 고도화.
  5. **에이전트 하네스 내장 (`AGENTS.md`, `.agents/rules/k8s-coaching-harness.md`)**:
     - 어느 컴퓨터에서 에디터를 열더라도 AI가 위 보안 규칙과 코칭 철학을 자동으로 로드하도록 설정 완료.
